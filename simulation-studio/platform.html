독립 실행 통제 플랫폼

Custos는 에이전트의 행동 제안과 실행 권한 판정을 분리합니다. 요청을 검증하고, 정책에 따라 허용·차단·승인 대기를 결정하는 통제 계층을 개발하고 있습니다.

PRODUCTCustos Control Plane

Agent와 등록된 도구 사이의 실행 권한 통제 계층을 지향합니다.

DECISION SCOPEAgent · 행동 · 리소스 · 정책

모든 AI 위험이 아니라 도구에 제출되는 구체적인 실행 요청을 대상으로 합니다.

INTENDED CUSTOMERSB2B / B2G

조직의 시스템·데이터·책임 구조에 따라 도입 범위를 계약으로 정의하는 모델입니다.

현재는 초기 연구 프로토타입입니다. 실제 고객 시스템 커넥터, 운영 배포 및 독립 보안 검증을 완료했다고 주장하지 않습니다.

HOW A REQUEST IS DECIDED

요청은 세 가지 결과 중
하나로 귀결됩니다.

정책 판정은 실행 명령이 아닙니다. ALLOW는 다음 실행 단계로 보낼 수 있다는 뜻이고, HUMAN_APPROVAL은 검토 전 보류, BLOCK은 실행을 허용하지 않는다는 뜻입니다.

01 / ALLOW

허용

현재 정책이 요청한 Agent·행동·리소스 조합을 허용합니다. 실행 어댑터로 전달하기 직전에 정책을 다시 확인합니다.

EXAMPLEresearch_agentread_database → research_db
02 / HUMAN_APPROVAL

사람의 승인 필요

요청은 실행되지 않고 만료 시각이 있는 승인 레코드로 보관됩니다. Reviewer가 승인한 뒤 원래 요청 Agent만 한 번 실행을 시도할 수 있습니다.

EXAMPLEresearch_agentsend_email → company_email
03 / BLOCK

차단

정책에 없거나 보호 대상으로 지정된 행동은 거부됩니다. 승인 버튼으로 우회할 수 있는 결과가 아닙니다.

EXAMPLEmodify_custos_policyprotected system action

위 예시는 현재 코드에 정의된 개발용 정책입니다. 실제 조직의 권한 모델이나 상용 보안 보장을 의미하지 않습니다.

PLATFORM COMPONENTS

요청에서 증거까지.
하나의 통제 흐름으로 연결합니다.

현재 프로토타입에 구현된 부분과 개발 목표를 구분해 설명합니다. 실제 외부 시스템 실행은 아직 연결되어 있지 않습니다.

01 / REQUEST GATE

요청 수신 및 검증

요청 주체는 설정된 Bearer 토큰으로 매핑됩니다. 행동·리소스·매개변수 형식, 크기, 민감 필드와 요청 ID를 검증합니다.

02 / POLICY

정책 기반 판정

기본 거부 정책은 허가된 에이전트·행동·리소스 조합만 통과시킵니다. 판정은 ALLOW, HUMAN_APPROVAL, BLOCK으로 나뉩니다.

03 / HUMAN REVIEW

사람의 승인 절차

승인 요청은 SQLite에 저장되고 만료됩니다. 검토자는 승인 또는 거부하며, 최초 요청 에이전트만 승인된 요청을 한 번 실행할 수 있습니다.

04 / IDEMPOTENCY

중복 요청 통제

동일 요청 ID와 동일 데이터의 재시도는 기존 결과를 반환합니다. 같은 ID에 다른 요청 내용을 넣으면 충돌로 거부합니다.

05 / AUDIT

감사 이벤트 기록

요청·정책 판정·승인·모의 실행 결과를 로컬 JSONL 로그에 해시 연결 방식으로 기록합니다.

06 / EXECUTION

실행 어댑터 경계

현재 구현은 모의 어댑터입니다. 실제 도구 연동 전에는 도구 자체에서 권한을 재검증하고 직접 우회 호출을 차단해야 합니다.

PLAIN-LANGUAGE GLOSSARY

통제 흐름에서 쓰는 여섯 가지 용어

01 / IDENTITY

Agent

작업을 제안하고 도구를 사용하려는 AI 또는 자동화 프로그램입니다. 현재 Custos는 설정된 Bearer 토큰으로 요청 주체를 구분합니다.

02 / INTENT

Action

에이전트가 하려는 구체적인 작업입니다. 예: read_database 또는 send_email.

03 / TARGET

Resource

작업의 대상이 되는 시스템이나 데이터 범위입니다. 예: research_db 또는 company_email.

04 / RULES

Policy

어떤 Agent가 어떤 Action을 어떤 Resource에 수행할 수 있는지를 정하는 규칙입니다. 정의되지 않은 조합은 기본적으로 거부됩니다.

05 / HUMAN REVIEW

Reviewer

HUMAN_APPROVAL 요청을 승인하거나 거부하는 검토 역할입니다. 현재 프로토타입은 개별 계정이 아닌 하나의 공유 개발용 Reviewer 토큰을 사용합니다.

06 / TOOL BOUNDARY

Execution Adapter

허가된 요청을 실제 도구에 전달하는 연결부입니다. 현재 구현은 MockExecutionAdapter이며 실제 외부 도구를 호출하지 않습니다.
