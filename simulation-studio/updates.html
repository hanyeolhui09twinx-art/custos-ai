DAY 007 / 03 NOV 2026 · SIMULATION LAB RELIABILITY

승인·시나리오 상태와 실험 경계를 보강

승인 대기 이력을 페이지 새로고침 이후에도 Run History에서 다시 열어 승인·거부할 수 있게 했습니다. 승인 직전에는 실행 게이트, 전역 승인 설정, Agent 상태·권한 범위, 현재 정책을 다시 확인합니다. 일시정지·정지 Agent 시나리오는 기존 상태를 보존하고, 장기 실행 중지 Trace의 잘못된 완료 표시를 수정했습니다. 멀티 Agent 화면은 실제 병렬 실행이 아닌 동기식·순차 평가임을 명시하고, 정책 판정과 승인 복구를 검사하는 새 자동화 테스트를 CI에 추가했습니다.

DAY 008 / 03 NOV 2026 · GUARDED EXECUTION BOUNDARY

실행 어댑터에 요청 결합형 허가 검증 추가

게이트웨이는 15초 유효한 HMAC 서명 Dispatch Permit을 발급하고, Guarded Adapter는 실행 직전에 요청 해시·서명·만료·1회 사용 nonce를 검증합니다. 현재 정책을 다시 평가하고, 승인 경로라면 SQLite에서 정확한 승인 건이 executing 상태인지 요청 해시와 함께 확인합니다. 위조·변조·만료·재사용·정책 철회·승인 ID 바꿔치기·동시 재전송 검사를 추가했습니다. 실제 외부 도구는 아직 연결하지 않았으며 서명 키와 재전송 캐시는 단일 프로세스용 연구 프로토타입입니다.

Day 8 개발 기록 읽기 ↗
DAY 009 / 03 NOV 2026 · SEPARATE MOCK TOOL PROVIDER

별도 제공자 프로세스에서 허가와 재전송을 다시 검증

게이트웨이 바깥의 별도 로컬 Tool Provider 프로세스를 추가했습니다. 제공자는 15초 HMAC 허가의 서명과 정확한 요청 지문을 독립적으로 확인하고, SQLite의 고유 nonce 기록으로 동시 재전송과 재시작 이후 재사용을 거부합니다. 통합 테스트는 정상 게이트웨이 전달, 무허가·위조·요청 바꿔치기 거부, 동시 재사용, 프로세스 재시작 후 재사용, 제공자 중단 시 BLOCK을 확인합니다. 제공자는 여전히 모의 도구만 실행하며, 같은 호스트의 두 프로세스일 뿐 OS 샌드박스나 실도구 격리를 증명하지 않습니다.

Day 9 개발 기록 읽기 ↗
DAY 010 / 03 NOV 2026 · EXECUTION RECEIPTS & RECOVERY

실행 결과 원장과 불확실한 결과의 재조정 추가

제공자는 Agent ID·request_id·요청 지문으로 SQLite 실행 영수증을 생성하고, 실행 전에 executing 상태를 기록합니다. 완료 결과는 저장해 동일 요청의 재시도에 반환하며, 다른 요청 내용으로 같은 ID를 재사용하면 충돌 처리합니다. 프로세스가 실행 도중 종료되면 executing 기록을 indeterminate로 복구하고 자동 재실행하지 않습니다. 게이트웨이는 응답을 받지 못한 경우 BLOCK으로 오해하게 만들지 않고 EXECUTION_UNKNOWN·executed=null을 반환하며, 동일 ID 재요청 시 제공자 영수증으로 결과를 조정합니다. 일반 실행과 승인 실행의 응답 유실, 완료 영수증 재사용, 페이로드 충돌, 중단 복구 검사를 추가했습니다. 이는 제공자 로컬의 at-most-once 호출 연구 구현이며, 실제 외부 도구의 exactly-once 효과를 보장하지 않습니다.

Day 10 개발 기록 읽기 ↗
DAY 011 / 03 NOV 2026 · GATEWAY RESTART RECOVERY

게이트웨이 재시작 후 요청과 승인 상태 복구

게이트웨이가 종료될 때 processing으로 남은 요청 영수증을 시작 시 indeterminate로 전환합니다. 같은 request_id로 재요청하면 기존 승인 ID를 우선 복구하고, 이어서 제공자 실행 영수증을 확인합니다. 기존 승인 대기 건은 중복 생성하지 않으며, 제공자 완료 영수증이 있으면 재실행 없이 저장된 결과를 복원합니다. 제공자 영수증이 없거나 불확실하면 EXECUTION_UNKNOWN 상태를 유지하고 자동 재전송하지 않습니다. 승인 실행 중 게이트웨이가 종료된 경로도 같은 영수증으로 복구합니다. 이 복구는 단일 게이트웨이 인스턴스만 지원하며 다중 워커용 lease는 아직 없습니다.

Day 11 개발 기록 읽기 ↗
DAY 012 / 03 NOV 2026 · AUTHENTICATED RECEIPT LOOKUPS

제공자 실행 영수증 조회에 HMAC 인증 추가

게이트웨이의 제공자 영수증 조회에 경로 결합형 HMAC 인증을 추가했습니다. 실행 서명 키에서 목적별 하위 키를 파생하고, GET 메서드와 URL 인코딩된 receipt 경로를 서명해 X-Custos-Receipt-Signature 헤더로 전달합니다. 서명 누락은 401, 위조 서명은 403으로 거부하며, 서명을 URL 쿼리에 넣지 않습니다. API 설정에서 키 전달을 연결하고 별도 프로세스 테스트로 정상·누락·위조 조회를 검사했습니다. 이는 인증된 루프백 HTTP 요청이지 TLS나 상호 TLS, 키 회전, OS 격리를 대체하지 않습니다.

Day 12 개발 기록 읽기 ↗
DAY 013 / 03 NOV 2026 · DISPATCH KEY-RING ROTATION

허가서 key_id와 수동 키 회전 경로 추가

DispatchPermit에 key_id를 추가하고 서명 대상 claim에 포함했습니다. 게이트웨이는 활성 키 ID로 신규 허가를 발급하고, 제공자는 설정된 키 링에서 허가의 key_id를 찾아 검증합니다. 영수증 조회 서명도 키 ID별 파생 키를 사용하도록 맞췄습니다. CUSTOS_DISPATCH_KEYS와 CUSTOS_ACTIVE_DISPATCH_KEY_ID 환경 설정으로 이전·신규 키 중첩 기간을 운영하고, 구형 발급기를 중단한 뒤 이전 ID를 양쪽 키 링에서 제거하면 폐기됩니다. 단일 키 환경 변수 default 호환은 유지됩니다. 이는 수동 환경 기반 회전이며 KMS/HSM, 자동 만료, 비밀 배포 자동화는 포함하지 않습니다.

Day 13 개발 기록 읽기 ↗
DAY 014 / 03 NOV 2026 · KEY COMPROMISE RESPONSE & LIFECYCLE AUDIT

키 등록·활성화·폐기 이력과 긴급 대응 절차 추가

게이트웨이와 제공자가 시작될 때 각자의 설정 키링을 기존 SQLite 상태와 비교합니다. 키 등록·활성화·폐기·동일 ID의 키 재설치를 구분해 DISPATCH_KEY_REGISTERED, DISPATCH_KEY_ACTIVATED, DISPATCH_KEY_REVOKED, DISPATCH_KEY_REPLACED 이벤트를 각 프로세스의 해시 체인 JSONL 로그에 기록합니다. 로그에는 키 원문이나 지문을 남기지 않으며, SQLite에는 변경 감지를 위한 SHA-256 지문만 저장합니다. 긴급 유출 시에는 중첩 회전을 하지 않고 제공자에서 손상된 ID를 먼저 제거한 뒤 재시작하고, 모든 게이트웨이의 설정도 새 ID와 키로 교체합니다. 이 기능은 시작 시 설정 비교이며 실시간 폐기 API나 원격 감사 저장소, KMS/HSM은 아닙니다.

Day 14 개발 기록 읽기 ↗
DAY 015 / 03 NOV 2026 · READ-ONLY SECURITY OPERATIONS

검토자 전용 키링 상태 및 감사 이벤트 조회 화면

GET /v1/security/overview를 추가해 검토자 Bearer 인증으로 Gateway와 Provider의 키링 상태를 조회합니다. 각 구성 요소의 활성 키 ID, 현재 허용 키 ID, 감사 로그에서 확인된 폐기 ID, 감사 체인 무결성을 요약하며 구성 요소·이벤트 유형·최대 개수 필터를 지원합니다. API는 키 수명주기 이벤트의 허용된 필드만 반환하고 요청 본문 등 일반 감사 데이터, 원문 키, 지문을 노출하지 않습니다. Security Operations 페이지는 이 API를 사용하는 이중 언어 읽기 전용 화면이며 토큰을 페이지 메모리에만 보관하고 지우기 기능을 제공합니다. Provider 데이터 조회 경로는 CUSTOS_PROVIDER_DB와 CUSTOS_PROVIDER_AUDIT_LOG로 API 프로세스와 Provider 프로세스 간 동일하게 설정합니다.
