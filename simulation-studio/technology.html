CUSTOS / TECHNOLOGY

실행 능력과 권한 사이에
검증 가능한 기술 경계를 둡니다.

Custos의 기술 방향은 요청 단위의 권한 검증, 실행 직전 재검증, 단일 사용 승인, 추적 가능한 이벤트에 기반합니다.

ENGINEERING PRINCIPLES

정책 판정은 에이전트의 자기 선언과
독립되어야 합니다.

에이전트가 요청에 포함한 역할 이름만으로 신뢰하지 않습니다. 서버가 가진 자격 증명 매핑과 정책을 기준으로 행동과 리소스를 확인합니다.

01 / IDENTITY

요청 주체 식별

현재 로컬 API는 Bearer 토큰을 설정된 Agent ID에 매핑합니다. 비대칭 키, 서명 요청, 위임된 신원 체계는 향후 과제입니다.

02 / SCOPE

행동·리소스 범위

정책은 허용된 행동과 리소스 조합을 명시합니다. 권한이 정의되지 않은 요청은 기본 거부합니다.

03 / APPROVAL

요청에 결합된 승인

승인 레코드는 요청 스냅샷과 해시에 연결됩니다. 만료, 검토자, 단일 실행 상태를 관리합니다.

04 / REVALIDATION

실행 직전 재검증

승인 후에도 정책이 바뀔 수 있습니다. 실제 실행 직전에 현행 정책을 다시 평가합니다.

05 / IDEMPOTENCY

요청 재시도 안전성

에이전트와 요청 ID를 멱등성 키로 사용합니다. 같은 페이로드의 재시도는 결과를 재사용하고, 다른 페이로드는 충돌 처리합니다.

06 / AUDIT

이벤트 무결성

로컬 JSONL 이벤트는 이전 해시와 연결됩니다. 이는 일부 조작 탐지에 유용하지만 원격 불변 저장소를 대체하지 않습니다.
