CUSTOS / SECURITY & TRUST

보안은 구호가 아니라
검증 가능한 경계입니다.

Custos는 연구용 보안 프로토타입입니다. 구현된 통제와 해결되지 않은 위험을 구분하고, 보장하지 못하는 것을 명확하게 공개합니다.

IMPLEMENTED CONTROLS

현재 코드와 테스트로 확인할 수 있는
통제 기능입니다.

아래 기능은 저장소 코드와 자동화 테스트에서 확인할 수 있는 범위입니다. 상용 보안 수준이나 알려지지 않은 공격에 대한 면역성을 뜻하지는 않습니다.

01 / DEFAULT DENY

기본 거부

알 수 없는 에이전트, 정책에 없는 행동, 허용 범위를 벗어난 리소스는 실행 전에 거부됩니다.

02 / HUMAN REVIEW

명시적 인간 승인

고위험 행동은 승인 대기 상태로 저장됩니다. 거부·만료된 요청은 실행할 수 없습니다.

03 / SINGLE USE

단일 사용 실행

승인된 요청은 원래 요청한 에이전트만 실행할 수 있으며 동시 재사용 시도는 원자적 상태 전이로 제한됩니다.

04 / RECHECK

실행 직전 정책 재확인

승인 이후 정책이 변경되어 현재 권한이 사라지면 실행 직전 차단합니다.

05 / INPUT BOUNDS

입력 경계 및 민감 필드 검사

요청 크기와 매개변수 크기를 제한하고 일반적인 비밀정보 필드명을 거부합니다. 자유 텍스트에 숨겨진 비밀을 전부 검출하는 DLP는 아닙니다.

06 / AUDIT

해시 연결 감사 로그

일반적인 로그 변경과 체인 단절을 탐지합니다. 관리자 권한 공격자가 전체 파일을 재작성하는 경우까지 막지는 못합니다.

THREAT MODEL

요청한 다섯 관점으로
보안 설계를 검토합니다.

각 관점은 장식적인 슬로건이 아니라 현재 아키텍처의 가정과 실패 가능성을 검토하는 문서 구조입니다.

01 / /ASSUMPTIONS

가정 — 통제 계층이 모든 경로에 있다

에이전트가 데이터베이스·메일·셸·클라우드 API에 직접 접근할 수 있다면 로컬 게이트웨이는 우회될 수 있습니다. 모든 특권 도구 호출이 통제 계층을 통과한다는 가정이 필요합니다.

02 / /BLINDSPOT

사각지대 — 아직 보호하지 못하는 영역

정적 토큰의 수명·회전·개별 검토자 계정·분산 실행·외부 불변 감사 저장소·실제 도구 격리는 아직 구현되지 않았습니다. 브라우저 콘솔은 개발용 토큰만 사용해야 합니다.

03 / /COUNTER

반론 — Custos가 새로운 단일 장애점이 될 수 있다

게이트웨이 호스트나 정책 출처가 침해되면 통제 계층 자체가 무력화될 수 있습니다. 독립 모니터링, 최소 권한, 격리와 복구 전략이 필요합니다.

04 / /EDGECASE

경계 사례 — 정상 흐름 밖에서 발생하는 실패

중복 요청, 동시 승인 실행, 만료, 요청 페이로드 변경, 정책 회수, 프로세스 충돌, 외부 실행 후 기록 전 장애, 시스템 시계 오류를 계속 시험해야 합니다.

05 / /SELFCRITIQUE

자기비판 — 테스트 통과는 우회 불가능성의 증거가 아니다

현재 자동화 테스트는 특정 입력과 상태 전이를 검증합니다. 실제 Agent 프레임워크와 격리된 도구 샌드박스에서 직접 우회 경로가 없다는 것을 입증하지는 못합니다.

전체 위협 모델과 경계 사례를 읽어보세요.

가정, 사각지대, 반론, 경계 사례, 자기비판과 다음 검증 관문을 더 자세히 문서화했습니다.

취약점 제보는 공개 이슈에 공격 절차를 게시하지 말고, 저장소의 보안 제보 정책에서 비공개 보고 가능 여부와 안전한 절차를 먼저 확인하세요.
