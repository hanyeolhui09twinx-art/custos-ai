# Day 012 — Authenticated provider receipt lookups

**Date:** 2026-11-03  
**Scope:** HMAC-authenticated provider receipt reads and request-path binding.

## Objective

The gateway must read the provider's execution receipt after a lost response, but the receipt endpoint should not be readable by every local process that can reach the loopback port. Add request authentication without putting signature material into URL query strings or access-log paths.

## Delivered

- Added a receipt-lookup HMAC subkey derived from the dispatch signing key using a dedicated context string (`custos-ai/provider-receipt-lookup/v1`).
- The gateway signs the exact `GET` method and encoded `/v1/receipts/{agent_id}/{request_id}` path.
- The signature is sent in the `X-Custos-Receipt-Signature` header; query parameters are rejected by the provider.
- The provider returns 401 when the receipt signature is missing and 403 when the signature is malformed or invalid.
- The provider verifies the signature with constant-time comparison before reading the receipt.
- `custos_api.py` now passes the configured dispatch key to `HttpToolProviderAdapter` for receipt authentication. Manual adapter construction must supply `receipt_signing_key` to enable reconciliation.
- Added a separate-process integration test covering missing, forged, and valid receipt lookup signatures.

## Verification boundary

This is HMAC request authentication, not transport encryption. Gateway and provider still share the development dispatch key through environment configuration; the receipt subkey is derived, not independently provisioned. There is no key rotation, service identity, mutual TLS, rate limiting, or OS/container isolation. A privileged host attacker can access the key and receipt database. Receipt lookups are read-only, so the path signature is reusable; replay protection is required for dispatch writes, not this read operation.

The provider remains a loopback-only mock service with no external tools or credentials. No real agent framework is connected.

## Next gates

1. Replace the shared development HMAC secret with managed service identities and key rotation.
2. Add authenticated transport (for example, mutual TLS) before moving receipt queries beyond loopback.
3. Add a recovery lease/ownership model before supporting multiple gateway instances.
4. Move the provider into a dedicated OS/container boundary with a separate service identity.
5. Integrate a real tool only after downstream idempotency and status-query reconciliation are defined.
