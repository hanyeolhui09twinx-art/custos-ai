# Day 020 — Read-Only SQLite Research Fixture

**Date:** 2026-11-03  
**Scope:** Local prototype / Provider process / synthetic data only

## Change

Replaced the Provider's mock research-read response with a narrowly scoped adapter backed by a local SQLite fixture containing three synthetic research records. The fixture is initialized at Provider startup; the runtime query connection is opened with SQLite URI `mode=ro` and `PRAGMA query_only=ON`.

The adapter accepts exactly one parameter, `query`. It must be a non-empty string of at most 160 characters and contain 1–8 searchable terms. Search terms are extracted from bounded Latin or Hangul tokens, supplied through SQL placeholders, and checked again using whole-token matching. The result is capped at five records.

The Provider execution adapter remains an explicit allowlist: `read_database/research_db` uses the read-only fixture; `send_email/company_email` uses the existing mock adapter. The email operation does not send anything.

## Validation

Added separate-Provider-process tests that verify:

- A permitted query returns the expected synthetic record.
- SQL-shaped search input cannot broaden the query result set.
- A runtime `INSERT` on the read-only connection raises `sqlite3.OperationalError`.
- `PRAGMA query_only` is active.
- Extra query fields are rejected before permit consumption and before an execution receipt is created.
- The OpenAI Agents SDK `FunctionTool` path returns the read-only fixture boundary note and stores the fixture result in the Provider receipt ledger.

## Limits

The fixture is synthetic local test data, not a real customer, production, or external database. Startup initialization writes the fixture file; execution-time research queries use read-only connections. This does not establish OS-level immutability against another process running as the same local user.

Email remains mock-only. The Provider is a separate local process, not an OS sandbox, container boundary, or production security perimeter. The prototype still lacks production TLS, independently verifiable Reviewer attestations, unique Reviewer identities, remote immutable audit storage, external security review, and full mediation of every Agent execution surface.

## Next engineering gate

Define typed, per-tool request and result schemas as versioned contracts, then replace the fixture-only data source with an explicitly configured least-privilege read-only connector. The connector must be unable to write by database permissions, not only by application convention. Add tests for credential scope, row-level authorization, timeout behavior, oversized results, and connector revocation before connecting any real customer data.
