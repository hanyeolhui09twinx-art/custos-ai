# Day 013 — Dispatch key-ring rotation

**Date:** 2026-11-03  
**Scope:** Key-ID-bound dispatch permits, overlapping provider verification keys, and manual key retirement.

## Objective

Replace the implicit single signing key with a key-ID-aware model so gateway and provider can rotate a key without dropping valid in-flight permits or receipt lookups.

## Delivered

- Added `key_id` to the immutable `DispatchPermit` claims. The ID is included in the canonical HMAC payload, so changing the ID invalidates the signature.
- `DispatchAuthority` now accepts a signing key ring and an active key ID. It issues new permits only with the active key while retaining configured keys for verification.
- The provider independently loads a key ring and validates the permit's exact key ID against it.
- Receipt lookup HMAC derivation is also key-ID-specific. `X-Custos-Receipt-Key-Id` selects the key used to verify the path-bound `X-Custos-Receipt-Signature`.
- The gateway receipt client signs reads with its configured active key ID.
- Added `CUSTOS_DISPATCH_KEYS` and `CUSTOS_ACTIVE_DISPATCH_KEY_ID` environment configuration to provider and gateway API.
- Kept `CUSTOS_DISPATCH_SIGNING_KEY` as a backwards-compatible single-key path, mapped to key ID `default`.
- Added process integration tests for active `v2` issuance, dispatch using previous and active keys during the overlap, previous-key receipt lookups, rejection after old-key retirement, and key-ID substitution.

## Manual rotation procedure

1. Configure the provider with both old and new IDs in `CUSTOS_DISPATCH_KEYS`; restart the provider.
2. Configure every gateway with the same overlap ring and set `CUSTOS_ACTIVE_DISPATCH_KEY_ID` to the new ID; restart the gateway.
3. Verify new permits and receipt reads use the new ID while old permits remain accepted during the overlap.
4. Stop all old gateway signers. Wait for the 15-second permit lifetime and deployment drain to pass.
5. Remove the old ID from both provider and gateway rings and restart. Old-ID permits and receipt lookups must now be rejected.

Removal is the revocation mechanism. There is no built-in timed retirement, KMS/HSM, independent service identity, automated distribution, or key compromise workflow. The same-host process and shared secret limitations remain.
