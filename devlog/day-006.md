# Day 006 — Conditional policy routing

**Date:** 2026-11-03  
**Scope:** Correct the homepage target-architecture diagram so it matches the three-way policy model.

## Objective

Make the first visual explanation of Custos technically consistent with the policy engine. Human review is conditional; it is not a mandatory stage for every request.

## Delivered

- Replaced the linear "human authority" stage with an explicit three-outcome policy branch.
- ALLOW is shown as eligible for dispatch-time revalidation.
- HUMAN_APPROVAL is shown as paused until a reviewer approves the exact request, then eligible for dispatch-time revalidation.
- BLOCK is shown as a terminal no-dispatch outcome.
- Added a final dispatch re-check, mock execution adapter, and local audit/evidence stage.
- Added narrow-screen layout rules for the three outcomes.
- Added regression checks that reject the old unconditional-human-review diagram and require all three policy outcomes.
- Added this engineering entry to the public Updates page and README index.

## Verification boundary

This is a product-explanation and UI change. It does not change the Python policy engine, approval store, API behavior, or execution adapter. The displayed architecture remains a target flow; the current Python adapter remains a mock, and real-agent/tool-boundary enforcement is not implemented.
