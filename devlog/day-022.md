# Day 022 — Machine-Readable Provider Tool Schema Catalog

**Date:** 2026-11-03  
**Scope:** Provider contract source of truth / local prototype

## Change

Published `contracts/provider-tool-contracts.v1.0.0.json` as the machine-readable catalog for both registered Provider tools. It declares JSON Schema Draft 2020-12 input and output schemas, exact Agent/action/resource bindings, contract versions, and required permit modes.

| Binding | Contract | Permit | Output |
|---|---|---|---|
| `research_agent / read_database / research_db` | `research_query_v1` `1.0.0` | `ALLOW` | `read_only` |
| `research_agent / send_email / company_email` | `email_request_v1` `1.0.0` | `APPROVED` | `simulated` |

The Provider loads the catalog at startup, validates its metadata and entry shapes, rejects duplicate bindings, checks semantic-version notation and declared schema dialects, and constructs the runtime registry from the catalog rather than maintaining a second hard-coded contract list.

## Runtime validation boundary

The local validator supports the subset used by the published catalog: object/string/integer/array types; required and additional-properties checks; string length and regular-expression patterns; the email format check used by this catalog; integer ranges; array length; and constant values. It is **not** a general-purpose, fully compliant JSON Schema Draft 2020-12 validator. Do not treat arbitrary third-party schemas as safely enforceable by this implementation.

## Limits

The catalog is machine-readable JSON Schema, but the Provider's local validator implements only the catalog's current keyword subset. The catalog is not an OpenAPI operation document and does not by itself create interoperability with arbitrary Agent frameworks or tool servers.

No customer/production database, external email service, or real external tool credentials are connected. Research reads remain confined to synthetic local records and email remains simulated. The Provider is a separate process on the same trusted host, not a sandbox or production security perimeter.
