# Day 007 — Simulation Lab reliability

**Date:** 2026-11-03  
**Scope:** Recoverable human approvals, safe scenario state handling, accurate traces, deterministic multi-agent disclosures, and behavior regression tests.

## Objective

Make the browser Simulation Lab more reliable as an educational control-flow simulator without implying that it is a real agent runtime or concurrency test environment.

## Delivered

- Added approval and denial controls to Run History for every persisted request in `PENDING_APPROVAL`, so a pending request can be reviewed after a page refresh or after another scenario is run.
- Centralized pending-request review in `reviewRun`. Before simulated approval dispatch, it re-checks the global execution gate, global approval switch, agent status, assigned action/resource scope, and current action policy.
- Added the global approval switch to the sequential experiment's approval revalidation.
- Preserved the pre-existing global pause and researcher status when a scenario temporarily simulates a paused gate or suspended agent.
- Corrected the long-running stop scenario so its trace records entry into a running state instead of falsely recording completed dispatch before the stop checkpoint.
- Renamed the Multi-Agent plan as a deterministic request plan, changed event labels from timing offsets to step numbers, and disclosed that the browser view is synchronous and does not test real parallel execution, race conditions, concurrent approvals, or distributed transactions.
- Added `tests/check_simulation_lab.js`, which exercises the policy decision function, approval revalidation, scenario state restoration, and long-running stop trace behavior.
- Added the new check to GitHub Actions, CONTRIBUTING.md, and the pull request checklist.

## Explicit limitations

- The Simulation Lab remains a browser-only deterministic simulator. It does not call a real agent framework, Worker, privileged tool, or external service.
- The Multi-Agent view evaluates a fixed request plan sequentially. It is not a stress test, race-condition test, or proof of distributed concurrency behavior.
- Browser-local run history and policy settings are simulation state, not production approval records or a security boundary.
