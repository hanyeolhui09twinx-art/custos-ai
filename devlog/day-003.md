# Day 003 — Corporate Website and Public Product Interface

**Date:** 2026-11-03  
**Scope:** Custos public website, product navigation, disclosure, accessibility, and feedback intake.

## Objective

Replace the earlier single-screen presentation with a structured corporate-style website that explains Custos as an independent AI execution-control research project. Preserve the existing browser simulator and local API console as tools within the same site rather than deleting or disguising them as a hosted product.

## Delivered

### Public website structure

Published these pages through GitHub Pages:
- Home — project overview, control architecture, and a client-side policy concept demo.
- Platform — request validation, policy evaluation, human approval, idempotency, audit events, and adapter boundary.
- Technology — identity, action/resource scope, request-bound approval, dispatch-time revalidation, and current implementation status.
- Security & Trust — implemented controls and explicit limitations, organized under the five lenses: ASSUMPTIONS, BLINDSPOT, COUNTER, EDGECASE, and SELFCRITIQUE.
- Research — research questions, roadmap, and engineering records.
- About — project purpose and current prototype status without unsupported claims about legal incorporation, customers, certifications, or deployments.
- Contact — structured public bug and research/collaboration intake.
- Privacy — data handling of the static website, browser simulation, and local console.
- Terms of Use — research/demo boundaries, local-console responsibilities, prohibited use, external links, and warranty limits.
- 404 — branded page-not-found route.
- Simulation Lab — the preserved original browser simulation.
- Local Control Room — the browser console for a Python API running on the user's own machine.

### Shared design and interaction

- Shared brand system, responsive navigation, footer, favicon, page descriptions, canonical URLs, Open Graph metadata, sitemap, and robots.txt.
- Korean/English switching with session-scoped preference.
- Keyboard skip links, main landmarks, Escape-to-close mobile navigation, focus restoration, and ARIA state announcements for the policy demo.
- Primary small-text controls use the darker brand accent. Its contrast against white is calculated at approximately 4.83:1; this is not a claim of a complete site-wide accessibility audit.
- Policy demo supports ALLOW, HUMAN_APPROVAL, and BLOCK example scenarios. Approval and denial are client-side demonstration states only.

### Feedback workflow

Added GitHub issue-form templates:
- .github/ISSUE_TEMPLATE/bug_report.yml for reproducible technical defects.
- .github/ISSUE_TEMPLATE/research_proposal.yml for design, adversarial testing, and collaboration proposals.
- .github/ISSUE_TEMPLATE/config.yml for guided issue entry.

Both forms warn users not to publish secrets, personal information, customer data, or confidential details.

## Explicit limitations

- GitHub Pages serves static files; the public website does not host the Python gateway.
- Simulation Lab and the homepage policy demo are not connected to real agents or external tools.
- Local Control Room only works when the user separately starts the loopback Python API and grants any required browser permission.
- The Python gateway still uses a mock execution adapter and is not production enforcement software.
- The website's automated tests validate source structure and scripted UI behavior; they are not a substitute for manual visual checks across Chrome, Firefox, Safari, desktop, and mobile devices.
- The public Pages site could not be independently rendered in the development environment during this pass, so final pixel-level browser review remains outstanding.
