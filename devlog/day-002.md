# Day 2 — Control-plane foundation

## Implemented

- Replaced the earlier minimal gateway with deny-by-default action/resource policy evaluation.
- Added strict request shape and size validation.
- Added a local HTTP API with Bearer-token-to-agent identity mapping.
- Added SQLite-backed human-approval state with expiry, reviewer decisions, requester binding, dispatch-time policy re-check, and single-use execution claim.
- Connected the gateway to the existing hash-chained JSONL audit log.
- Hardened audit append behavior to reject a broken or externally changed chain.
- Added automated gateway/API/audit tests and a GitHub Actions CI workflow.

## Current execution boundary

The only execution adapter is a mock. The "read database" and "send email" operations do not connect to a database or send messages. The API binds to loopback by default and rejects remote binding.

The hosted browser Simulation Studio remains a separate static simulation. It is not yet connected to this API.

## Security caveats

The local Bearer-token mapping is a development credential mechanism, not a complete agent identity system. The audit hash chain is tamper-evident for ordinary edits, not immutable storage. There is no distributed transaction between approvals and an external tool.

## Next

1. Pass the automated CI suite.
2. Connect the browser Studio to a safe local API workflow or add a dedicated local control console.
3. Implement an isolated adapter contract and failure/retry tests before any real tool integration.


## Additional hardening and browser console

- Added request idempotency keyed by authenticated agent and stable request ID. Exact retries return cached results; altered payloads using the same ID conflict.
- Added atomic one-time approval execution claims and tests for concurrent execution attempts.
- Rejected common raw credential field names from request parameters before they can be persisted to approval records or audit events. Managed reference keys ending in ref/reference remain usable.
- Bounded request body and parameter sizes and converted deeply nested JSON into a 400 response rather than an internal error.
- Added a bilingual Local API Console page linked from the Studio sidebar. It holds entered tokens in page memory only, calls the loopback API from an explicit user action, and uses a strict CORS origin allowlist.
- Added browser Loopback Network permission handling and explicit loopback address-space declaration for current Chromium-based browsers.
- Added Node-based inline JavaScript syntax/security-wiring validation to CI.

The hosted Studio and Local API Console are deployed through GitHub Pages. The Python API still runs locally, binds to loopback only, and uses mock execution. Browser-to-local API interaction depends on browser loopback permission and has not been manually verified across browsers in this environment.
