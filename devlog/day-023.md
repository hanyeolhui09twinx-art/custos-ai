## Change

Added `contracts/compatibility/provider-tool-contracts.baseline.v1.0.0.json` as the initial compatibility baseline for the published Provider catalog. Added `tests/test_contract_compatibility.py` with a small SemVer-aware compatibility check.

## Version rules enforced by the tests

- A change to an existing contract's input schema, output schema, input kind, or required permit mode requires that contract's version to increase.
- Any structural contract change also requires the catalog version to increase.
- Adding a binding requires a minor-or-major catalog version increase.
- Removing a binding requires a major catalog version increase.
- Catalog and per-contract versions may not move backwards.

The compatibility test compares exact contract structures and intentionally treats schema metadata changes as catalog/contract changes too. Future releases must consciously refresh the baseline and update versions as part of the same reviewed change.

## Limits

This is a CI compatibility policy, not an automated migration system or complete semantic classification of every JSON Schema change. It detects structural changes and requires explicit version movement; humans must still decide whether a changed contract is backward-compatible, breaking, or warrants a major release.

The Provider continues to enforce only the subset of JSON Schema Draft 2020-12 used by the published v1.0.0 catalog. No real customer database, email provider, or arbitrary external tool server is connected.
